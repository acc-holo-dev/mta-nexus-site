## Native элементы и общие компоненты

Семантика HTML и оформление — разные уровни. Общий Button уже рендерит настоящий button; Input добавляет подпись и ошибку к input. Нативный select сохраняет привычный системный выбор, table — структуру данных, anchor — переход и открытие новой вкладки. Само отсутствие React-обёртки не является дефектом. [Button](https://github.com/acc-holo-dev/mta-nexus-site/blob/385e577e7443cf7d7b817419ce5c3b8afe87b690/packages/ui/src/button.tsx#L4-L49), [Input](https://github.com/acc-holo-dev/mta-nexus-site/blob/385e577e7443cf7d7b817419ce5c3b8afe87b690/packages/ui/src/input.tsx#L23-L53).

| Назначение                          | Элемент и поведение                                                        |
| ----------------------------------- | -------------------------------------------------------------------------- |
| Перейти к странице или файлу        | Anchor/Next Link, href, стандартные действия браузера                      |
| Отправить или изменить состояние    | Button с явным type и подтверждённым результатом                           |
| Выбрать значение из обычного списка | Native select с label; combobox только при конкретной потребности поиска   |
| Сменить локальную панель            | Tab/tabpanel со связью ID и keyboard navigation                            |
| Перейти между маршрутами            | Навигационные ссылки с aria-current, без искусственного превращения в tabs |

Общий рецепт ButtonLink/CardLink должен согласовать размеры, radius, padding, font и focus. Карточка может быть одной ссылкой; дополнительный Join, Save или Copy не вкладывается внутрь неё. Клавиатурный focus заметен в обеих темах. Для основных touch controls предложен ориентир около 44 px, а compact desktop остаётся явным вариантом. Текущие 24/32 px не объявляются автоматически нарушением стандарта. Массовая смена default type Button без проверки форм запрещена как неподтверждённая правка.

## Формы и сохранение работы

У текстового поля, select и textarea одинаковая модель: label, optional hint, значение, invalid/error, disabled, readOnly и pending. Подпись доступна независимо от placeholder. Ошибка связана с полем через ID; общий отказ сети или конфликт не маскируется под ошибку каждого поля. API code переводится в человеческий RU/EN текст, внутреннее исключение не становится инструкцией пользователю.

Input уже умеет связывать label/error. Общая оболочка Field должна переиспользовать это поведение и native controls, а не заменять системную клавиатуру, required или maxlength. Причина отключённого действия видна без hover; readOnly значение можно прочитать и скопировать. [Существующий field chrome](https://github.com/acc-holo-dev/mta-nexus-site/blob/385e577e7443cf7d7b817419ce5c3b8afe87b690/packages/ui/src/field-classes.ts#L1-L9).

**Alert tier.** Полевая ошибка — `role="alert"` у Input; отказ экрана/секции — один `ErrorState` с `role="alert"`. В `site/src` не изобретают сырой `role="alert"`; только эти `@nexus/ui` поверхности. Политика: `tests/ui-field-alert-honesty-policy.test.ts`.

После нажатия отправляется определённая редакция. Пока запрос идёт, поля либо временно блокируются, либо последующие изменения явно остаются новой несохранённой редакцией. Переход после успеха не должен молча уничтожать позднюю правку. При ошибке сохраняется ввод и доступен безопасный повтор. Success появляется после подтверждения ожидаемого объекта и состояния; timeout, пустой ответ или несовпадающая квитанция не означают успех. У FollowButton уже есть полезный образец checking/error/confirmed success; сохраняем существующие guards. [Follow states](https://github.com/acc-holo-dev/mta-nexus-site/blob/385e577e7443cf7d7b817419ce5c3b8afe87b690/apps/web/src/components/follow-button.tsx#L139-L218).

## Диалоги таблицы и короткие экраны

Действующие More и notification panels используют native dialog и useModalDialog. Их focus containment, inert background, Escape и return focus нужно сохранить. Экспортируемый UI Dialog сейчас не используется в app; его ограничение нельзя приписывать реальному shell. Предложение общего modal компонента должно опираться на действующий native pattern. [Текущий modal hook](https://github.com/acc-holo-dev/mta-nexus-site/blob/385e577e7443cf7d7b817419ce5c3b8afe87b690/apps/web/src/components/use-modal-dialog.ts#L5-L49).

У длинного диалога доступен заголовок и закрытие, содержимое прокручивается в пределах доступной высоты с safe area. Для More и SectionHeader сначала проверяются реальные bounding boxes, начало/конец списка и длинные RU подписи; риска по классам недостаточно для заявления о поломке. Новый ConfirmAction — предложение: он показывает объект, масштаб и последствия, но сохраняет password, slug, revision, audit и отмену существующего действия.

Таблица остаётся table. При overflow нужна именованная область keyboard scrolling, понятный focus, caption и связи заголовков. Колонки получают явное выравнивание и формат; длинный UUID не должен разрушать всю страницу. Native server statistics уже даёт хороший образец. [Statistics table](https://github.com/acc-holo-dev/mta-nexus-site/blob/385e577e7443cf7d7b817419ce5c3b8afe87b690/apps/web/src/components/server-statistics-panel.tsx#L13-L29), [caption и headers](https://github.com/acc-holo-dev/mta-nexus-site/blob/385e577e7443cf7d7b817419ce5c3b8afe87b690/apps/web/src/components/server-statistics-panel.tsx#L95-L118).

## Общая Home и навигация

Сохраняется принятая общая Home для гостя и аккаунта: конечные секции с дальнейшим переходом, без обязательного dashboard redirect. Personal changes summary — предлагаемая реализация полезного персонального модуля, а не новое утверждённое название главной или доказанная механика удержания. Гость понимает площадку и может читать публичное; защита действия не превращает всё знакомство с продуктом в registration wall. [Решение Home](PRODUCT.md).

Для protected navigation нужно выбрать единое правило: скрыть пункт либо показать честный вход/onboarding CTA. Видимая ссылка на Admin сама по себе не является обходом серверных прав. Workspace группирует реальные объекты и доступные возможности, позволяет совмещать роли и сохраняет личный контекст при работе с организацией. Политика гостевых пунктов остаётся предметом решения, а не автоматически принятой рекомендацией аудита. Исправление ссылки Open Library на существующую `/workspace/library` выполняется отдельно от этого выбора, без ожидания редизайна навигации. [Текущий destination](https://github.com/acc-holo-dev/mta-nexus-site/blob/385e577e7443cf7d7b817419ce5c3b8afe87b690/apps/web/src/app/market/[slug]/page.tsx#L424-L430).

В каталогах URL — источник filters, sort и pagination. Back и sharing сохраняют выдачу; смена фильтра сбрасывает курсор, но не независимые параметры. Вкладка, которая меняет только выделение, не выполняет обещанную фильтрацию. Server card различает просмотр, Join и копирование адреса; профиль связывается только с установленной NEXUS identity. Неизвестное число игроков не становится нулём или offline.

## Ресурс автор версия и получение

До получения ресурса человек должен понять назначение, публичного автора/организацию, версию и состав выдачи. Автор показывается из безопасной публичной проекции; private ID, email и скрытая identity не заменяют профиль. Author и current owner не смешиваются без domain contract. Ссылки Trust и Publications имеют отдельные области и расстояние. [Принятые цели resource page](RESOURCES.md).

Free — цена, Open/Closed Source — способ выдачи исходников, license scope/term — условия использования, DRM — отдельная применимая возможность. Одно не выводится из другого. Новая source metadata требует согласованной схемы и unknown/default; отсутствие данных не заполняется догадкой. Production DRM не изображается действующим в бесплатной beta.

Выбранная версия согласована между названием действия, историей, инструкцией и разрешённым артефактом. Нельзя обещать один build, выдавая другой. Получение доступа, начало скачивания, завершение передачи, установка и успешная работа на сервере — разные события. UI называет только подтверждённый результат; отсутствие telemetry не создаёт статус Installed. Серверные права и safety guards повторно проверяются по FLOWS.

Single acquire и сбор бесплатного набора различимы. После входа сохраняется исходное намерение, но мутация не исполняется без необходимого подтверждения. Owned, pending, unconfirmed, error и receipt имеют понятные действия; «Открыть библиотеку» ведёт к библиотеке или записи. Корзина и безопасные повторы уже есть, повторять их логику в UI нельзя.

Описание может получить предложенные секции «Назначение», «Установка», «Настройка», «Ограничения», «Поддержка». Код форматируется и копируется без выполнения. Compatibility остаётся optional; неизвестное не называется совместимым или несовместимым. Помощь передаёт разрешённый resource/version context без публикации приватных сведений. [Optional compatibility](RESOURCES.md).

Gallery уже существует; lightbox — отдельное предложение. Авторский readiness overview также предложение: он собирает существующие формы и реальные блокеры, сохраняя черновик. Optional metadata не становится новым обязательным publishing gate. Preview не равен публикации, а заполненный checklist не заменяет clean scanner result.

## Метки состояния и понятные числа

Статусы и accessible labels локализуются в RU/EN. Technical enum допустим в подробностях оператора, основной label остаётся человеческим. Verification, scan result, membership/access, moderation, reputation, achievement и Sponsored обозначают разные свойства. Цвет усиливает подпись, но не заменяет её.

При ratingCount=0 сообщаем отсутствие отзывов, а не низкую оценку 0.0. Перед подписью salesCount проверяем событие, которое его изменяет: имя столбца и иконка не доказывают смысл метрики. Нельзя называть claim count установками. Empty отличается от failed request, а unknown — от измеренного нуля. Конкретный catch-fallback server reviews, который заменяет ошибку загрузки на пустой список и total=0, должен показывать недоступность; это не утверждение о всех страницах отзывов. [Конкретный fallback](https://github.com/acc-holo-dev/mta-nexus-site/blob/385e577e7443cf7d7b817419ce5c3b8afe87b690/apps/web/src/app/servers/[slug]/page.tsx#L90-L102).

Типографические роли проверяются по computed styles, включая shorthand font и overrides. Длинные ошибки и инструкции остаются читаемыми при 200% текста; reduced motion и существующие contrast checks сохраняются. Theme system preference и storage fallback работают после изменений. Новый theme picker не обязателен без решения.

## Будущий рекламный интерфейс

Следующие правила образуют проект для F5. Приняты fixed-price direction, явная маркировка и запрет скрытого изменения органического score; конкретные слоты, lifecycle, no-fill, пользовательские controls и метрики ещё требуют согласования. Наличие sponsored badge не означает готовый placement service. Оплата и реальные обязательства рекламодателю относятся к отдельной F6. [Существующая граница рекламы](UX-CONTRACT.md).

Реклама/Sponsored и рекламодатель понятны до клика, включая mobile card. Редакционная рекомендация и служебное сообщение имеют другие названия. Органические результаты выбираются независимо; placement вставляется только в разрешённое место, не меняет reviews/popularity/trust и не покупает Clean Build или verification.

Предлагается исключить ads из auth/recovery/security, подачи жалобы, acquire confirmation и административных действий; точная матрица должна быть принята. Рекламный CTA не выглядит кнопкой скачивания. No-fill, expired, failed и quarantined target оставляют страницу работоспособной. Поздняя вставка не перемещает кнопку под пальцем; fallback не рисует фиктивную активность.

Why shown объясняет тип причины без private/anti-abuse signals. Opt-out не допускает скрытого behavioral ranking под другим названием. Hide/report привязаны к конкретному placement; правила повторного показа и жалобы определяются до реализации. Отдача слота, видимый показ, клик и полезное действие имеют разные единицы, дедупликацию и период. Пустое место не доказывает выполненное рекламное обязательство. [Opt-out и explainability](UX-CONTRACT.md).

## Проверка результата

Приёмка включает полезный исход и существенные отказы, а не только наличие компонента, selected tab или зелёный axe. Ready screenshot ждёт итоговый контент; loading/empty/error снимаются и называются отдельно. Evidence содержит SHA, fixture и состояние. Кадр с skeleton не доказывает зависание production; CI fixture не является пользовательской статистикой.

Проверяются затронутые RU/EN, light/dark, keyboard, narrow/desktop и pending/error states. Общий тяжёлый прогон координируется после интеграции; не запускается отдельно каждым исполнителем. При подтверждённом исправлении обновляется соответствующая карточка и контракт; непроверенное помечается явно. Новый UI showcase допустим только как принятое средство этой проверки, без автоматического создания публичного раздела.
