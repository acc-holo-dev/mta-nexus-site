# Безопасность и доверие

Технические границы описаны в [архитектуре](../ARCHITECTURE.md); ниже — их продуктовый смысл и маршруты к подробным контрактам. Утверждённые цели находятся в [реестре](13-DECISION-REGISTER.md).

## Обязательные границы

- Публичный build опубликован, имеет чистую проверку с provenance сканера и временем. Таймаут, отсутствие сканера и неполная проверка не означают clean. ClamAV должен сообщать о превышении лимитов через `AlertExceedsMax`.
- Файлы приватны, ключи неизменяемы. Размер и SHA-256 проверяются при передаче из открытого файла; отмена запроса освобождает чтение. Ошибка целостности блокирует выдачу.
- Сервер проверяет действующие сессию, владельца, контекст и разрешения. Browser mutation проверяет происхождение. Публичный URL-валидатор не заменяет SSRF-защиту серверного запроса.
- Приватные ответы не кэшируются публично. Пароли, токены, секреты сессий, ключи лицензий и raw evidence не попадают в публичные DTO, логи или отчёты.
- Критические изменения данных и обязательный аудит транзакционны. Событие описывает известный факт: начало скачивания не является завершённым скачиванием.
- Подписка, платная публикация, высокий trust и verification не обходят hard safety/finance controls, ограничения запросов и проверки артефакта.

## Семантика доверия

| Факт | Значение |
|---|---|
| Контроль endpoint или внешней ссылки | Доказано конкретное управление; это не качество сервера/автора и не универсальное одобрение. |
| Verification | Подтверждено конкретное свойство на основании evidence; статус может пересматриваться. Его нельзя купить. |
| Отзыв | Есть допустимое взаимодействие и контекст версии/покупки; право оставить отзыв проверяется отдельно. |
| Репутация | Несколько доказуемых сигналов и история, а не один непрозрачный платный score. |
| Жалоба | Вход для расследования, а не публичный обвинительный вердикт. |
| Malware clean | Результат конкретной проверки; он не обещает абсолютной безопасности и не отменяет повторную авторизацию. |

## Санкции и расследования

Целевая лестница: предупреждение → действие над контентом → ограничение capability → временная блокировка → постоянный бан. Тяжесть и evidence могут требовать немедленного строгого действия.

Публичный `SCAM`/`BLACKLIST` требует определённого субъекта, дела, доказательств, staff-решения, содержательной причины, даты, аудита и апелляции. Такой вердикт действует до пересмотра. Публичная история различает active/expired/overturned/appealed и не стирается молча после снятия предупреждения. Секреты, PII и детали обхода защиты редактируются безопасно; публичная причина сохраняет смысл.

Карантин прекращает новые скачивания/активации подозрительного build, сохраняя артефакт и evidence. При подтверждённом malware нужны уведомления ранее скачавшим, а не только takedown. Публичная Transparency-статистика содержит методологию и агрегаты без приватных материалов.

Апелляция — отдельное дело/событие. Для тяжёлых решений по возможности назначается другой reviewer. Финансовый доступ, расследования и raw provider payloads требуют отдельных полномочий.

## Аккаунт и каналы

Целевой Security Center объединяет сессии, историю входов, 2FA, recovery codes, отзыв и alerts. 2FA рекомендуется для ценных аккаунтов; сама роль Seller/Server Owner/Organization Finance/Staff не делает её обязательной. Чувствительное действие может требовать re-auth/step-up по риску или правилам провайдера.

Почта восстановления использует ограниченные одноразовые токены и защищённую доставку; конфигурация ключей, TLS, outbox и восстановления — в [эксплуатации](../OPERATIONS.md). Состояние очереди не доказывает доставку.
