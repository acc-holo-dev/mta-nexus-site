## 4. Блокеры (требуют действий владельца)

### P0 — GitHub Actions не выполняет jobs

Фиксируется только в настройках GitHub (репозиторий/организация), не в коде:
runner assignment завершается с `runner_id: 0`, jobs содержат `steps: []`
(последний наблюдаемый запуск — [run 36398395028](https://github.com/acc-holo-dev/mta-nexus-site/actions/runs/36398395028)).
Действия: проверить Actions policy, runner availability, billing/quota, ограничения
workflow-уровня; после восстановления — rerun CI на точном SHA текущего `main`
и `pnpm release:verify`. Запуск воркфлоу без выполненных шагов не является release evidence.

## 5. Риски и рекомендации для дальнейшей разработки

1. **CI — единственный источник доверия.** Пока Actions не восстановлены, любые
   мержи в `main` держат риск недоверицированного дрейфа (как этот). После
   восстановления CI включить обязательные checks для push в `main`
   (Settings → Branches → Required status checks).
2. **Root-тесты и воркспейс.** Долгосрочно: перенести root `tests/` в пакеты
   (`apps/web/tests`, `packages/db/tests`) — уберёт необходимость root-зависимостей
   и ускорит резолвинг. Сейчас это допустимо (зависимости зафиксированы явно).
3. **Runtime тестового прогона.** `fileParallelism: false` увеличил полный сьют до
   ~65 c (было ~13 c параллельно). Это цена детерминизма для синглтон-очереди;
   при желании вернуть скорость — выделить mail-сьюиты в отдельный vitest-проект
   со своей БД, не трогая остальные.
4. **Dev-БД vs тестовая БД.** Прогон `pnpm test` на dev-БД валиден (capacity-тесты
   теперь самодостаточны), но для герметичности использовать `pnpm test:isolated`.
   Dev-БД содержит ~440 пользователей демо-данных — не смешивать с production.
5. **Docker-контекст.** `.github` включён в контекст намеренно (surface-тесты);
   следить, чтобы туда не попали тяжёлые артефакты.
6. **Хост-тулинг.** Хост имеет Node 22.23.2 / pnpm 12.4.1, проект требует
   Node ≥ 26 / pnpm 12.4.2. Либо обновить хост-тулинг (`nvm install 26`),
   либо работать через Docker-путь (`pnpm dev`, контейнерный toolchain) —
   иначе `pnpm check` на хосте невозможен.
7. **Зависимости.** `pnpm audit` чист; Dependabot настроен (`npm_and_yarn`,
   weekly). Очередная dependabot-ветка удалялась как неактуальная — проверить
   открытые PR после восстановления CI.
8. **Документация.** Политика «только два длинных документа» сохранена; этот
   аудит — датированное evidence, обновлять его не нужно.
