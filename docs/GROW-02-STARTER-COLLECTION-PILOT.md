# Редакционные стартовые подборки — пре-пилотный бриф (GROW-02)

**Статус:** пре-пилотный бриф (документация только). Пилот не запущен; численные эффекты, сроки, бюджеты и нагрузки не измерены. Запуск требует явного решения владельца и отдельного разрешения на любые внешние публикации/приглашения/рассылки (`limits`). Контракт подготовки карточки — п.5 «Карточка пилота до старта» в [docs/RETENTION-PLAN.md](RETENTION-PLAN.md).

Этот файл исполняет требование карточки «До запуска: brief…» для «ограниченного пилота поддерживаемых стартовых подборок». Он задаёт объём, порядок действий, ограничения и способ проверки — **до** появления измерений. Существующие частные коллекции не изменяются этим документом.

## Проверяемый тезис

Готовый поддерживаемый путь экономит время новичку. Ограничитель (из §2 RETENTION-PLAN): постоянное обновление и проверка ограничений. Проверка — по решённой задаче пользователя и времени сопровождения, **не** по числу созданных коллекций (акцепт GROW-02 п.4).

## Акцептные условия карточки (как зафиксировать в брифе)

1. **Выбраны ограниченные темы и редактор; источник каждого ресурса и дата проверки указаны.**
   - Число тем: небольшое, перечисляется в брифе до старта (TODO — перечень тем заполняет владелец).
   - Редактор: назначается владельцем; не подразумевается self-назначение.
   - Формат каждой записи ресурса: `источник` (URL/репозиторий/издание) + `дата проверки` + результат проверки (годен/устарел). Пустые места — до старта.
2. **Порядок действий и ограничения понятны; работоспособность всей связки подтверждается отдельной проверкой.**
   - Цепочка: выбор темы → отбор ресурсов → проверка → публикация подборки → обновление → фиксация даты/времени. Проверка сквозного пути — отдельным шагом (check), не подразумевается автоматически.
3. **Редакционный/перенесённый материал помечен; устаревание и предложенное исправление видны.**
   - Вводится пометка «редакционная» / «перенесённая» и поле статуса проверки; устаревшая запись показывает предложенное исправление, а не исчезает молча.
4. **Проверяется решённая задача пользователя и время сопровождения, а не число коллекций.**

## Минимальный шаг и границы

- **Минимальный шаг (из §2):** несколько редакционных материалов/коллекций с автором и датой проверки.
- **Объём пилота:** ограниченное число тем (TODO), ограниченный период сопровождения, без автоматизации публикации.
- **Ограничение нагрузки:** подлежит определению владельцем до старта (число ресурсов на тему, периодичность проверки, время редактора).
- **Право завершить:** пилот прерывается в любой момент без обязательств.

## Ограничения (limits карточки)

- Пилот ещё не проведён; численные эффекты, сроки и бюджеты не измерены.
- Внешние публикации, приглашения и рассылки этим брифом/пакетом **не выполняются** — нужна явная команда владельца.
- Редактор/автор не подменяется формой контента: нужен назначенный ответственный и зафиксированная дата проверки.
- Никаких автоапдейтов и автоматического обнаружения окружения (см. также [docs/SERVER-PACK-SPEC.md](SERVER-PACK-SPEC.md)).
