# Dependency maintenance

This repository keeps `main` as reviewed release history and `dev` as the integration branch. Automated version updates must preserve that boundary.

## Dependabot version updates

`.github/dependabot.yml` monitors:

- npm/pnpm manifests from the workspace root;
- GitHub Actions used by workflows;
- the root Dockerfile.

All version-update pull requests target `dev`. Minor and patch npm updates are grouped separately for production and development dependencies to reduce pull-request noise; major npm updates remain individual reviews.

The configuration lives in Git, but GitHub reads Dependabot configuration from the repository's default branch. The current default branch is `main`, so a draft change on `dev` does not activate Dependabot before the normal release/promotion process places the configuration on `main`.

## Security-update boundary

Dependabot security updates are separate from version updates. GitHub raises security-update pull requests against the default branch. Using `target-branch: dev` for version updates does not redirect security updates.

Do not treat an automated dependency pull request as automatically safe to merge. It must pass the same project verification and release evidence rules as any other change.

## Review policy

For dependency pull requests:

1. preserve the lockfile generated by the package manager;
2. review release notes for breaking/runtime/security changes;
3. require project typecheck, tests and build;
4. require browser/production checks when the dependency affects those surfaces;
5. keep major updates isolated unless there is a strong reason to combine them;
6. never merge directly to `main` just because the update is automated.

The initial configuration deliberately does not auto-merge anything and does not grant Dependabot write access beyond creating its normal update pull requests.
