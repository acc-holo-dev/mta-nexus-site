## Для кого и какую задачу решаем

MTA NEXUS объединяет публичные серверы Multi Theft Auto, ресурсы, сообщество, контент и marketplace вокруг общей идентичности и доказуемого доверия. Один человек может одновременно играть, публиковать ресурсы, владеть сервером и участвовать в организации; onboarding не закрепляет его навсегда в одном разделе.

| Для кого              | Польза                                                                                                          |
| --------------------- | --------------------------------------------------------------------------------------------------------------- |
| Игрок                 | Найти действующий сервер, понять состояние, следить за обновлениями, участвовать в сообществе                   |
| Владелец сервера      | Подтвердить контроль, управлять страницей и командой, публиковать события, находить ресурсы                     |
| Автор ресурса         | Показать версии, происхождение, зависимости и проверки; распространять работу безопасно                         |
| Команда / org         | Управлять общими объектами и разрешениями без передачи личного аккаунта                                         |
| Покупатель и продавец | Понятные условия лицензии, доставки, обновлений, поддержки и споров (**цель**; платежи в free beta не включены) |
| Staff                 | Обрабатывать обращения по полномочиям, сохранять доказательства, объяснять решения и апелляции                  |

Ценность ближайшей **бесплатной beta** — законченные пути от интереса к результату: найти ресурс или сервер, понять автора и ограничения, получить доступ, вернуться к объекту, задать вопрос и увидеть ответ. Владелец проекта должен безопасно обновлять сервис и восстанавливать данные.

## Действующая граница (current runtime)

Код закрытой беты распространяет **бесплатные** ресурсы; реальные платежи, выплаты и production DRM **не** включены. Платный marketplace, подписки и seller-opt-in DRM — утверждённое направление ([COMMERCIAL-FUTURE](COMMERCIAL-FUTURE.md)).

Все публичные серверы из master list видимы независимо от регистрации владельца. Claim открывает управление и доказывает контроль, но **не** условие появления в каталоге. Live-данные не подменяются редактором страницы ([SERVERS-ORGS](SERVERS-ORGS.md)).

## Приёмка по пользовательским путям

| Путь                             | Минимальное завершение                                                                            | Существенные отказы                                            |
| -------------------------------- | ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| Гость → ресурс → вход            | Выбранный объект и безопасное намерение сохранены; после входа доступен понятный следующий шаг    | Истёкшая ссылка, удалённый объект, отказ прав, повторный вход  |
| Каталог → карточка               | Видны автор, описание, актуальная доступность и источник показателей; фильтры сохраняют смысл URL | Ошибка загрузки ≠ пустая выдача ≠ неизвестный online           |
| Получение → библиотека → версия  | Понятна выдаваемая сборка; latest и выбранная версия различаются                                  | Quarantine, отзыв доступа, отмена, потеря ответа, смена сессии |
| Публикация → модерация → доступ  | Автор видит требования; публична только допустимая сборка                                         | Конфликт, неуспешный scan, draft, отзыв                        |
| Обсуждение → ответ → уведомление | Черновик/контекст сохранены; unread фильтрует реальный список                                     | Таймаут, удаление, mute, недоступный объект                    |
| Сервер → профиль → клиент        | Действие в ожидаемый контекст; connect intent ≠ доказанное участие                                | Клиент не установлен, status неизвестен                        |
| Support/staff → решение          | Контекст сохранён, полномочия на сервере, аудит                                                   | Истёкшая сессия, fresh-auth, конфликт прав                     |
| Релиз сайта → среда              | Exact digest, проверенный комплект, recovery plan                                                 | Неуспешная миграция, старый образ, недоставленный alert        |

Подробности — FLOWS / UX-CONTRACT / предметные контракты и карточки `planning/tasks.json`.

## Home / Discover (owner target)

Общая Home для гостя и аккаунта: конечные секции с дальнейшим переходом, без обязательного dashboard redirect. Гость понимает площадку и читает публичное; защита действия не превращает всё знакомство в registration wall. Personal changes summary — proposal полезного модуля, не новое имя главной ([37-HOME…](PRODUCT.md), [UX-CONTRACT](UX-CONTRACT.md)).

## Принципы развития

- Ценность — в связанных сценариях: найти сервер, автора, обновление, получить ресурс, следить за проектом.
- Реальные данные и происхождение показателей; заглушки и будущие функции не выдаются за действующий результат.
- Проверка артефакта, право доступа и репутация — разные смыслы; платёж не покупает доверие.
- Удержание — на пользе и обслуживаемых циклах ([RETENTION-PLAN](RETENTION-PLAN.md)).
- North Star и окончательный слоган не блокируют обычную разработку.

## Что не обещать как готовое

Личные сообщения, полноценные groups/clans, календарный сервис, versioned server pack, 3D preview и in-game проба — будущие направления; их не делает «готовыми» наличие support, Organization, gallery или LibraryCollection ([COMMUNITY](COMMUNITY.md), [RESOURCES](RESOURCES.md)).

Реклама: staff-managed pilot (F5) vs self-service/checkout/payouts/DRM (F6). Органика, verification и безопасность файла не продаются скрытно.

Нет измеренного % удержания, подтверждённой ёмкости production-host или календарной даты выпуска из одного только наличия документов.
